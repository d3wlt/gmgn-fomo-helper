# better gmgn v0.49.0

## Highlights

This release fixes the reported GMGN developer-tooltip behavior, makes holder indicators represent people followed on FOMO, restores trade visibility for tokens whose FOMO token feed is empty, and uses usernames instead of display nicknames. It preserves the wallet-tracker virtual-list positioning from v0.47.x and the followed-user tracker injection from v0.48.x.

- The watched-developer detail card opens only from the compact **M / L / rate / ATH** metrics badge, not from hovering the rest of the GMGN card.
- The 👥N token badge now counts FOMO users you follow who hold that token; its tooltip lists their usernames when available.
- Followed FOMO users are highlighted directly in the popup **Holders** tab with a **★ Following** badge.
- The popup **Trades** tab keeps both buys and sells and labels them clearly with **Buy**/**Sell** and **First**, **More**, **Partial**, or **All** position actions.
- If FOMO's per-token feed returns no trades, the extension retrieves the top holders' trade details and reconstructs their token-specific swap history instead of showing a false empty state.
- FOMO usernames (`userHandle`) are shown without the leading `@` in the popup and followed-user tracker rows, rather than the display nickname.
- Flap tax badges open the explicit English tax-information page.
- The extension reads the current FOMO following IDs through the existing browser-local FOMO session, fetches recent FOMO trading activity, and filters it to followed users before returning it to the GMGN page.
- Followed-user buys, sells, and theses are inserted chronologically among native GMGN tracker rows.
- Followed events use a subtle highlighted background, a **★ Following** marker, buy/sell/thesis icons, and compact position-action badges.
- Transaction-aware deduplication keeps a followed event from appearing twice when GMGN already shows the same native trade.
- Existing FOMO event-type switches and blocked-token controls still apply.
- FOMO's `430`/`431` unauthorized responses now use the existing session-refresh path.
- Malformed, `success:false`, and unexpected application-status FOMO payloads are rejected instead of being cached as successful empty results.
- Slow panel responses are discarded after account, token, or tab changes instead of repainting the new view.
- Account-bound followed-user caches and in-flight requests are retired on account changes while same-account token refreshes continue without a false disconnect.
- Concurrent trade-history fallbacks are coalesced, followed-holder retries use bounded backoff, and transiently failed detail requests are not cached as valid empty histories.

## Installation

Download the ZIP and matching checksum from this repository's GitHub Release. Verify the checksum, extract the archive to a permanent folder, enable Developer mode at `chrome://extensions` or `edge://extensions`, select **Load unpacked**, and choose the extracted folder.

## Usage

Sign in to FOMO in the browser so the extension can mirror the session locally. On a GMGN token page, open the extension's FOMO panel and select **Trades** to see buy and sell activity with position labels. Select **Holders** to see followed accounts highlighted. Token chips across supported GMGN chains show the number of followed FOMO users holding each token. Open GMGN's **Tracker** tab to see recent buys, sells, and theses from users you follow on FOMO mixed into the time-ordered tracker feed.

Followed-user rows are marked **★ Following**. The arrow/star icon identifies buy, sell, or thesis activity, and the adjacent badge shows the position action where FOMO provides or allows it to be derived. Hover the compact watched-developer metrics badge to open its developer detail card.

## Updating

Replace the files in the existing unpacked-extension folder with this release, then select **Reload** on the extension card. Refresh the GMGN tab afterward so its virtual tracker list is recreated cleanly.

## Security and privacy

The extension contains no analytics, remote executable code, wallet signing, or transaction execution. FOMO authentication remains in browser-local extension storage and is sent only to FOMO's API for the documented holder, narrative, trade, and following-feed requests. The following list is used only to filter FOMO activity before display. This project is independent and is not affiliated with the supported services or the original upstream author.
