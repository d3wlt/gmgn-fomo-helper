# better gmgn v0.53.8

## Highlights
- Handle synchronous throws and rejected promises from the followed-holder badge loader after extension invalidation.
- Stop future holder requests in the obsolete page context, clear holder caches/retry state, and reject late successes from outstanding requests. A refreshed page starts normally.
- Preserve retry/backoff for transient worker errors. Native QuickBuy and passive FOMO collection are unchanged.

## Installation
Extract ZIP and use Load unpacked in chrome://extensions with Developer mode enabled.

## Usage
Use GMGN/FOMO as before. Reloading an extension invalidates old page contexts; refresh the page to activate the new extension. Native quick buy may execute a trade when clicked according to GMGN settings.

## Updating
Replace files, reload the extension, then refresh GMGN and FOMO. Existing Errors-panel entries are historical and are not deleted by this fix.

## Security and privacy
No CSP relaxation, request interception change, analytics enablement or financial action. FOMO page CSP errors attributed to the passive fetch wrapper are a separate issue and may still appear. Regression tests execute the production loader with synthetic runtime failures; no real trade is used for testing.
